# Ant Arena 三维化迭代计划

日期：2026-11-12
状态：**仅计划，未执行**。当前先保留 2D 可玩版供试玩，不在本轮修改代码、下载素材或接入模型。

## 1. 目标与启动条件

把当前 Cocos 2D 战场升级为接近参考截图及僵尸参考工程的 2.5D 三维战场：正交近正俯视且略偏斜、格子有厚度、地表浅坑有凹凸、蚁穴有立体结构、昆虫/替代单位有低模体积与接触阴影，并具备真实攻击动作、弹丸轨迹和拖尾。大厅、卡牌、HUD 继续使用现有 2D UI。

**启动前必须先通过三个门槛：**

1. 用户试玩当前版本，确认战斗节奏、出兵、染色、奖励、升级和存档逻辑基本可用。若逻辑需要调整，先改逻辑，不用三维化掩盖玩法问题。
2. 先按 `docs/spark.md` 重新审视全部兵种职责、克制关系与 FSM，确认“点击即出兵、独立模型 + 数量、工蚁 5 块循环、战斗兵先拆方块、影子对战”等新规则。不能保留一套用户看不懂的旧行为后只换模型。
3. 开始任何素材搜索或三维编码前，**先询问用户可演示低模版本及对应模型地址**。用户提到手头可能有若干地址，这些地址优先于代理自行搜索。

本计划不代表已找到任何模型，也不代表任何素材许可已确认。

## 2. 默认保持不变的范围（Spark 明确重审的除外）

- 除 Spark 重审部分外的 `core/`：能量、格子、AI、节奏与 RNG。
- `controller/flow.ts`：大厅、战斗、结算、奖励、收藏状态流。
- `viewmodel/` 的画面快照契约；若新增库存、铺设计数、撤退和拖尾状态，先扩展 VM，不在视图层另存规则。
- 现有 2D 大厅、收藏、奖励、教学与设置界面。
- 现有 Node 测试、Release 验证和 Debug-only 测试接口。

三维化与兵种行为重审必须拆成小任务，不把“换模型”和“改规则”混成一次大改。任何 Spark 新规则先写纯逻辑测试与单个三维垂直样例，确需调整数值时另开独立任务并跑 `tests/ant-pacing.test.ts`。

## 3. 执行前必须向用户确认的问题

在 Task 1 启动时一次性确认，不自行猜测：

1. 可演示版本及模型地址是什么？是否允许下载并商用？
2. 用户提到的小汽车、小坦克分别想替代哪些兵种？是否仍保留蚂蚁、蝎子、幼虫等虫形单位？
3. 是否接受 CC-BY 署名素材，还是只接受 CC0？
4. 蓝红换色、卡通低模、写实度、模型面数和目标设备有什么限制？
5. 用户提供的素材是否有指定比例、朝向、动画名称和授权要求？

若用户暂时没有地址，再按第 4 节顺序搜索。小汽车/小坦克只是候选替代造型，不默认改变兵种名称与机制。

## 4. 素材优先级与许可流程

### 4.1 优先级

1. **用户提供的演示链接和模型**：先检查适配度、许可、格式与动画。
2. **CC0 低模虫形/小型单位**：优先寻找 ant、beetle、scorpion、insect、bug、larva、termite、queen、roly-poly 等。
3. **低模小汽车、小坦克、机械虫/玩具单位**：仅在用户认可替代方向后使用。
4. **基础几何体组合**：找不到合适模型时，用胶囊、球体、圆角盒、圆柱和自定义 Mesh 组合，不硬凑风格不符的素材。

候选来源顺序：poly.pizza → Quaternius → Kenney。GLB/glTF 优先，FBX/OBJ 仅作备选。

### 4.2 下载与审查规则

- 下载只放 `/tmp/ant-arena-assets/`，审查通过后再复制进项目 bundle，不直接污染仓库。
- 默认只收 CC0；CC-BY 单独列备选，必须经用户接受署名后才能采用。
- 每个素材记录来源 URL、许可页面或包内 License、三角面数、贴图、骨骼和动画段名。
- 在暂存目录生成 `INVENTORY.md`，包含来源许可、目录结构、兵种映射、详细清单、备选、缺口和复现下载命令。
- 不使用“搜索到就算可用”的素材：必须在 Cocos 中实际加载并截图验收。

## 5. 代码生成低模的方案

### 5.1 地表与格子

- 共享 Box/Beveled Box 几何，不为每格创建独立高面数模型。
- 蓝/红/米白格使用同一 Mesh，实例化显示；侧壁略暗于顶面，保留细格线与阶梯轮廓。
- 中立格只加少量砂点或微色差，避免整屏噪点。
- 永久障碍使用代码网格拼出凹形浅坑：外沿顶面、内侧面、坑底三层，不能再用平面绿色块代替。

### 5.2 蚁穴

用径向分段自定义 Mesh（lathe）生成八边形陶土台：外台、斜面、内圈、深黑洞四部分。蓝红各一套材质，洞口保持近黑，不加摧毁血条。

### 5.3 腐叶砖与装饰

- 砖块使用圆角立方体，顶面亮、侧面暗；搬运时跟随载体，销毁后隐藏。
- 草叶用少量低面数三角片/锥体，碎石用低细分球体，集中在地图边缘，避免遮挡战场。
- 弹丸使用低细分球体 + 拖尾 Mesh；命中用短暂星形闪光，不做屏幕震动。

### 5.4 兵种模型

- 优先用户指定模型；其次 CC0 虫形模型；最后才使用用户认可的小汽车/小坦克或程序化组合模型。
- 同一模型通过材质替换形成蓝红阵营，不为双方复制不同 Mesh。
- 按卡面保留识别色：Worker 蓝橙、Soldier 紫红、Scorpion 黄绿、Dung 黄蓝、Larva 蓝紫等。
- 模型只需少量关键动作：出巢、行军、攻击、受击、死亡。Queen 产兵、Dung 击退、Scorpion 弹丸、Roly 架炮必须能读出差异。

## 6. 目标技术结构

```text
core / flow / viewmodel（保持纯逻辑，不 import cc）
                 │
                 ▼
       BattleView3D（只读 BattleVM）
       ├── ArenaCameraRig       正交相机与视口适配
       ├── TerrainMeshView      格子、浅坑、草地、砖块
       ├── NestMeshView         双蚁穴
       ├── UnitMeshPool         单位模型池、阵营材质、等级角标
       ├── ProjectileMeshPool   弹丸与命中特效
       └── BattleHud2D          现有顶部 HUD 与底部五卡
```

- 3D 场景与 2D HUD 分层渲染，输入仍通过统一 `screenToGrid`，不能把命中规则写进 Mesh。
- 模型池复用节点；静态地形共享 Mesh，禁止每帧重新创建几何。
- 可短暂保留 2D 渲染回退用于 A/B 截图，但最终交付不增加玩家可见的调试开关。

## 7. 小任务拆分

### Task 0：试玩反馈与基线冻结

- 用户确认逻辑可接受，记录需要优先修正的问题。
- 保存当前 192 项测试、Release 和代表截图作为回归基线。
- 若逻辑未通过，停止三维化，先开玩法修复任务。

### Task 1：确认用户模型地址与许可

- 询问第 3 节全部问题，读取用户提供的演示与模型。
- 输出候选映射、许可与缺口，不下载到仓库。

验收：每个候选都能回答“从哪来、能否商用、给哪个兵种用”。

### Task 2：CC0 素材检索与暂存清单

- 仅在用户没有合适地址或明确需要补充时执行。
- 在 `/tmp/ant-arena-assets/` 下载、实测面数/动画并生成 `INVENTORY.md` 和联系表。

验收：12 个兵种均有“模型 / 用户认可替代 / 程序化兜底”之一，无未确认许可的素材。

### Task 3：单场景三维技术样例

- 一个格子、一个浅坑、一个蚁穴、一个候选单位，正交相机与基础灯光。
- 同屏放置当前 2D 对照图，先确认比例、视角、阴影和低模风格，不批量生产。

验收：Cocos Web Mobile 实机可见且截图风格获用户认可；未确认前不进入全量替换。

### Task 4：代码地形 Mesh

- 完成阶梯格、凹形浅坑、双蚁穴、砖块和边缘装饰。
- 保持 18×30 坐标与现有 VM 一致。

验收：格子染色与现有 owner 同步，点击坐标无偏移，轮廓外不生成 Mesh。

### Task 5：候选单位导入与规范化

- 统一 GLB 尺寸、 pivot、朝上/朝敌方向、蓝红材质、面数与动画段。
- 先 Worker、Soldier、Scorpion 三个代表兵种，再扩展其余兵种。

验收：在实际格子大小下轮廓可辨，无贴图丢失、骨骼报错、巨大/微小模型或错误朝向。

### Task 6：BattleView3D 替换

- 接入现有 BattleVM、单位池、搬砖、弹丸、炮台、等级和 Time's Up。
- 保留现有 HUD 与全部回调。

验收：选卡部署、战斗、染色、死亡、结算与当前逻辑一致；192+ 测试无回归。

### Task 7：动画与视觉反馈

- 出巢 stagger、行军、近战前冲、弹丸、受击、死亡缩小淡出、开箱与结算弹性。
- 不添加镜头推拉、屏幕震动或血腥效果。

验收：动作不驱动规则，暂停/结算时动画也冻结，无 tween 泄漏。

### Task 8：性能与最终验收

- 100+ 单位场景压测、双视口、完整胜/负/奖励/升级/存档流程。
- 检查 Draw Call、三角面数、纹理内存、GC、console/pageerror 和 Release 无测试 hook。

验收：全部测试、类型检查、Debug/Release 浏览器验收通过；目标设备帧率达标且无持续掉帧。

## 8. 回退与风险控制

| 风险 | 应对 |
| --- | --- |
| 用户模型风格与参考差异大 | 先做 Task 3 单场景确认，不批量接入；必要时改程序化组合模型 |
| 许可不明 | 不采用；换 CC0 或程序化 Mesh |
| 骨骼动画在 Cocos 报错 | 先用静态 GLB，动画后补；不为动画强行换引擎或依赖 |
| 模型面数/贴图过大 | 减面、共享材质、合图、实例化；不牺牲核心可读性 |
| 三维化改变点击位置 | 继续用 VM 网格坐标做射线/平面拾取，并用部署测试校准 |
| 试玩发现逻辑问题 | 暂停三维化，先修逻辑，避免双线返工 |

## 9. 完成定义

只有同时满足以下条件，才可称为“2.5D 三维复刻版”：

- 战场使用真实 Mesh/正交相机，不是 2D Graphics 模拟厚度。
- 所有兵种有经确认的三维造型或程序化替代，蓝红可辨，技能表现完整。
- 现有玩法、结算、奖励、升级和存档无行为回归。
- 参考画面对照覆盖格子侧壁、浅坑、蚁穴、砖块、单位和阴影。
- 全部自动化测试与 Release 实机验收通过，素材许可清单完整。
