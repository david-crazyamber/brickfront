# Ant Arena 迭代 Notes

日期：2026-11-12
用途：记录本次实现中的裁定、风险和未来调整入口。不是新增需求，也不要求立即修改。

当前状态：2D 可玩版已完成；三维化仅有 `docs/3d-iteration-plan.md`，尚未执行。验收记录见 `docs/verification.md`。

## 1. 工程与协作裁定

1. **不创建工作树、不提交 git**
   - 原因：用户没有要求 git 写操作。
   - 风险：没有 commit 可用于恢复，主要依赖工作区文件。
   - 调整入口：需要备份或分享时，由用户明确决定 commit/branch。

2. **子任务串行**
   - 原因：避免多个实现者同时修改共享工作区。
   - 风险：总耗时更长。
   - 调整入口：只有文件完全独立的资产检索/文档任务才考虑并行。

3. **`.meta` 在集成阶段统一生成与验证**
   - 原因：避免每个子任务手写 UUID 和反复变更。
   - 风险：中间阶段可能缺 meta，最终必须重新跑 Creator 导入审计。

4. **固定 `createBattle(seed, deck, levels, tutorial)` 契约**
   - 原因：把卡牌等级和首局教学显式传入战斗。
   - 风险：调用方若继续只传前两个参数，会使用默认等级与非教学模式。

5. **允许 Task 5 修改 `battle.ts` 接入完整单位系统**
   - 原因：原计划遗漏了基础 march 与正式 `tickUnits` 的必要集成点。
   - 风险：扩大单次修改面，需要保留全部旧战斗测试。

6. **AI、初始兵种、解锁兵种分组实施；解锁兵种再分两组**
   - 原因：控制每个子代理的任务规模。
   - 风险：任务与审查轮次较多，但不是功能拆分需求。

7. **AI 在 `tickBattle` 前调用**
   - 原因：避免 runtime 循环 import，并固定决策顺序。
   - 风险：未来新增驱动入口若漏掉 `tickOpponent`，红方不会出牌；测试应固定顺序。

8. **大厅、战斗、收藏曾使用临时预览**
   - 原因：提前做真实构建与截图验证。
   - 风险：预览种子和调试全局可能进入正式版；交付前已移除，后续不得恢复无门控预览。

## 2. 视觉与内容裁定

9. **每日宝箱按原图采用 6 格，而非 PRD 的 5 格**
   - 原因：`ref/level.jpg` 实际为 6 格，截图优先。
   - 风险：旧五格存档可能多一个可领箱位。
   - 调整入口：`core/profile.ts` 的 `CHEST_SLOTS`、大厅 VM、相关测试必须一起改。

10. **卡牌/宝箱使用截图裁切，战场单位与地形使用 Graphics 近似**
    - 原因：保留卡面造型并快速完成可玩版。
    - 风险：不是严格 1:1，缺少三维厚度、字体、动画和角色细节。
    - 调整入口：按 `docs/3d-iteration-plan.md` 做真实 Mesh 战场；不要继续堆 2D 修补。

11. **锁定七卡只来自灰色卡面，教官使用遮罩**
    - 原因：参考目录没有更亮或无遮挡素材。
    - 风险：锁卡颜色偏浑浊，larva 腿部有徽章形缺口，教官不是完整透明立绘。
    - 调整入口：优先向用户索取原始模型/立绘，不把近似恢复色当作原素材。

12. **不恢复用户已有的 `ref/` 改名/删除**
    - 原因：这些改动早于本实现且由用户持有。
    - 风险：原始 17 张中有 2 张在当前工作区没有对应内容。
    - 调整入口：若后续需要完整证据集，由用户决定是否从初始提交恢复，不能擅自覆盖。

## 3. 玩法与平衡裁定

13. **巢穴从边缘改为红 `(8,4)`、蓝 `(8,25)`**
    - 原因：避免红巢被倒计时遮挡、蓝巢压到底部。
    - 风险：首波行军缩短约 4 格，接敌提前。
    - 调整入口：修改 `core/battle.ts` 巢常量后必须跑全部核心测试和节奏测试，不要只改视图坐标。

14. **铺地兵种与战斗兵采用不同后续目标**
    - 规则：Worker/Larva/Dung 到首航点后寻找最近中立格，其他战斗兵直推敌巢；Worker 搬砖、Tiger 突袭、Termite 啃砖、Roly 架炮优先。
    - 参数：Worker 速度 1.4，Dung 速度 0.85。
    - 风险：可能改变交战顺序、铺地吞吐和搬砖经济；没有铺地兵的卡组尚未验证中立清空表现。

15. **节奏采用统计验收，而不是每局硬落 60–80 秒**
    - 规则：5 个固定 seed 的清零中位数在 60–80 秒，且每局不超过 80 秒。
    - 实测：42.7 / 59.5 / 61.0 / 63.5 / 71.3 秒，中位数 61.0。
    - 风险：中位数距下限只有 1 秒；42.7 秒的一边倒局仍偏快；5 个 seed 不是完整平衡证明。
    - 调整入口：任何移速、费用、AI、伤害或扩张规则变化，先跑 `tests/ant-pacing.test.ts`，不要改阈值来掩盖回退。

16. **弃战不扣杯**
    - 原因：本地休闲模式允许随时退出。
    - 风险：玩家可通过退出规避失败扣杯。
    - 调整入口：若奖杯需要竞争性，应改成弃战按失败结算，并同步页面流测试。

17. **每日宝箱用完后仍发普通金币/碎片**
    - 规则：`chest = -1` 时不再推进箱格，但仍可能获得战斗奖励。
    - 风险：每日金币没有硬上限。
    - 调整入口：若需要严格每日上限，应在 `settleBattle` 中对 `chest < 0` 不发奖励或只给奖杯，并更新测试。

18. **Rhino 冲锋与卡牌等级缩放，Roly 使用独立炮台状态**
    - 原因：保持每级 +10% 的统一成长和“滚动到点后架炮”语义。
    - 风险：会改变高等级 Rhino 的首击伤害；炮台身份应读 `turretDeployed`，不能只看 `state`，因为攻击时为 `combat`。

19. **存档 key 固定为 `ant-arena.profile` 并兼容旧 v3 key**
    - 原因：避免未来 schema 升级时因改 key 丢档。
    - 风险：多 key 并存期间需要保留回退读取；保存失败时内存和磁盘可能短暂不同步，但当前策略不会重复发奖。
    - 调整入口：新增字段必须改 schema/迁移，不要通过换 key 清空旧进度。

20. **调试接口只允许 Debug 构建**
    - 规则：Release 不暴露 `__antTest`、旧 demo 或预览接口；步进时冻结实时循环。
    - 风险：Release 包仍可能有未执行的函数体死代码，不能仅凭字符串判断后门，应检查运行时和调用点。
    - 调整入口：发版前执行 `node tools/verify-ant-browser.mjs --release`，确认 hook 为 `undefined`。

## 4. 当前最重要的后续顺序

1. 先由用户试玩并反馈逻辑问题，优先修玩法而不是先做美术。
2. 逻辑稳定后，执行三维计划前，先向用户确认可演示低模版本和模型地址。
3. 再确认许可和兵种替代关系，然后做单个三维样例，用户认可后才批量替换。
4. 每次平衡调整都同时跑核心测试、节奏测试和 Release 浏览器验收。
